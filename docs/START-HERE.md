# 第一次使用：从资料到公开网址

你需要：电脑、能读写本地文件的 AI 工具、Node.js 18+、一个托管账号。模板本身免费；AI 工具与托管的收费、额度以各自服务为准。

## 先体验，再安装

先打开 [示例网站](https://tstbswwswbst.github.io/tcc-trip-site/)，试按天切换、展开每日时间线和预算。下载 [最新 Release](https://github.com/tstbswwswbst/tcc-trip-site/releases/latest) 的 `trip-site-skill.zip`，解压后应看到 `trip-site/SKILL.md` 和 scripts、assets、references 文件夹。

如果只想先试成品，下载 `trip-site-demo.zip`，解压并双击 index.html；无需运行构建。这个成品是设计示例，不是你的定制行程。

## 让 AI 读到完整文件夹

把解压后的 trip-site 文件夹放进 AI 工具当前工作目录；支持技能导入时按当前界面导入。不支持安装也没关系：在对话中明确要求“读取这个文件夹里的 SKILL.md 并执行”。

只粘贴 SKILL.md 而不提供 assets、scripts，会缺模板。只把 zip 给一个不能解压和执行的聊天模型，也不会自动变成网站。

## 给资料，不填大表格

复制 README 中的提示词，补目的地、天数、人数和喜好。粘贴你已有的行程文本；若给票据截图，先遮掉姓名、电话、证件和订单号。要求 AI 先提取已有信息，只问影响行程的缺项。

看到“待确认”很正常：让 AI 帮你补来源，或你自己确认。尤其检查地名是否重名、坐标是否同一地点、房价是否乘过房数与晚数。

## 打开成品

AI 应交付一个 output 文件夹。双击 index.html；点选某一天，展开日程，打开随身摘要。想修改时对 AI 说：

> 把第三天改得轻松一点，保留已有酒店。修改同一份 trip.json，然后重新生成网站和卡片，列出你改了什么。

如果工具只有命令行，在 trip-site 文件夹运行：

```sh
node scripts/build.mjs assets/example.json output
```

这只构建示例。定制时让 AI 用你的 `trip.json` 替换输入路径。

## 拿到网址

愿意让 AI 帮忙操作终端：优先 Surge。完全不想终端：登录 Netlify，把 output 拖入 Drop。详见 [发布说明](../skills/trip-site/references/deploy.md)。首次登录是你要做的一次人工操作，不需要把密码发给 AI。

发布后把真实链接发给一个朋友，让他在自己的手机上打开。关掉你电脑不会关闭托管站点，但本地修改只有重新部署后才会上网。

## 常见卡点

| 看到什么 | 怎么处理 |
| --- | --- |
| node 不是命令 | 安装 Node.js 后重开终端/AI 工具，再执行 `node --version` |
| AI 只给 JSON | 要求它读取 scripts/build.mjs 并构建，交付 output 中的 HTML |
| 页面没有街道底图 | 默认是可离线交互的路线示意，并非加载失败；需要街道底图时让 AI 阅读数据约定中的地图服务说明 |
| 某天没有点 | 该天无已确认坐标，文字行程仍可读；补来源与 GCJ-02 坐标后重新构建 |
| 手机打不开链接 | 确认不是 localhost/file 地址；检查站点可见性和移动网络，必要时换托管服务 |
| 网站显示旧内容 | 确认上传到原站点/原域名，刷新缓存，检查最新部署时间 |
| 想算 AA | 当前预算是计划小计；请单独整理实际支出与付款人，不能将预算直接导入结算 |

反馈时提供问题步骤、设备、公开示例截图，不上传未脱敏的真实出行票据。

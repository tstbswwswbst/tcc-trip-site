# Trip Site · 把行程做成值得分享的网站

目标是可用成品，不让用户逐格填写表单。用户负责偏好和最终确认；AI 负责提取、查证、组织和构建。

## 开始

读 [数据约定](references/data-contract.md)，以 [江南示例](assets/example.json) 为结构参考。只补问会影响行程的缺项（目的地、日期或天数、人数、预算口径），已有资料不重复询问。允许先做带“待确认”的草稿，不把模型猜测变成预订事实。

将资料写为 `trip.json`。门票、开放时间、交通班次、价格和酒店信息需有来源和核查日期；无法查证时使用“待确认”，不能借用示例价格。未知金额写 null，零只代表已确认免费。坐标需记录坐标系和来源，未知则 null；不凭记忆编造精准坐标。

## 生成

使用本技能自带模板和脚本，不重新发明地图组件、不固定江南地名。

```sh
node scripts/build.mjs /absolute/path/trip.json /absolute/path/output
```

脚本位置相对于本技能目录；输出目录须是独立、用户允许写入的目录。Node.js 18+，构建无 npm 依赖。得到 `index.html`（精美网站）、`card.html`（随身摘要）、`trip-card.json`（旧 trip-card 兼容数据）和 `build-report.json`。三者来自同一份数据，修改时改 JSON 后重建。默认不把输入原始资料放进公开输出目录。

模板继承 reference-original.html 的配色、字体层次、山峦首屏和地图侧栏。参考原稿只用于审美比较，其历史票价、时间及坐标均非已核验资料。需要个性化时先改标题、文案、配色和行程；改变布局仍须保留下面的交互契约。

## 不可退化的交互

- 任意城市、任意天数可生成；选择一天只画当天点和连线，全部路线可恢复；单点和无坐标日不崩溃。
- 城市聚焦、地点弹窗、每日时间轴以及“在地图查看”相互可达。
- 地图上的线仅是游览顺序示意，不能称为真实道路导航或计算车程。真正导航用地点外链。
- 底图或 Leaflet 不可用时，保留可读行程、地点列表与外链，不把其他模块一起卡死。
- 预算区分人均和全团，不能把估算冒充实际 AA 账单；未知费用要计入“未完整”说明。
- 390px 手机屏幕按钮可触达，无横向溢出；卡片是辅助出口，不取代精美站点。

## 查验和交付

在能执行浏览器的环境检查：桌面、手机、Day 切换、弹窗关闭（含 Esc）、返回地图、预算、卡片链接、外链坐标顺序、无网降级。记录真实执行结果；没有浏览器时明说未实测，不声称通过。

公开版本删去订单号、联系人电话、房间号、真实同行人姓名与精确入住安排等不需要展示的资料。预订资料不进入 URL 编码；链接压缩不是加密。生成输入报告中列出待确认项目，让用户容易审阅。

用户要求上线时读 [发布说明](references/deploy.md)。已有发布授权即执行可用的已认证路径；需要登录时让用户本人在服务商界面完成，保留完成的本地作品。不要承诺匿名永久托管、国内必达、免费无限流量，也不要把 localhost 当公网链接。新手文案应是“给资料 → AI 做网站 → 首次登录托管 → 获得链接”，不是无条件一键上线。
